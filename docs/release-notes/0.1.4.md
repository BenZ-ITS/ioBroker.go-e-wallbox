## English

### What changed

- The names of all channels and states are available in all languages of ioBroker (English, German, Russian,
  Portuguese, Dutch, French, Italian, Spanish, Polish, Ukrainian, Chinese). English and German are written by hand,
  the other languages are machine translated.
- If the wallbox reports a key without a value (`null`, e.g. `pgrid` while it receives no PV data), the adapter no
  longer writes `null` into the state. A state is only created once the wallbox delivers a value; an existing state
  keeps its last value.
- `info.friendlyName` has the role `text` (before: `info.name`), because it can be written. `info.rssi` has the role
  `value.rssi` (before: `value`).
- Additional API keys that differ only in upper/lower case (e.g. `tpa` and `TPA`) are used once.
- The readme links the website of the manufacturer.

### Impact

- After the update, the adapter sets the new names and roles on its existing objects when it starts. State ids and
  values are unchanged.
- States that currently hold `null` keep it until the wallbox reports a value for them.
- Scripts that relied on `null` to detect a missing value have to use the timestamp of the state instead.

### Why

- These are findings of the review for the ioBroker adapter repository: every state needs a name in all languages,
  the value of a state has to match its type, and the role has to match the read/write flags.

## Deutsch

### Was sich geändert hat

- Die Namen aller Kanäle und Datenpunkte gibt es in allen Sprachen von ioBroker (Englisch, Deutsch, Russisch,
  Portugiesisch, Niederländisch, Französisch, Italienisch, Spanisch, Polnisch, Ukrainisch, Chinesisch). Englisch und
  Deutsch sind von Hand geschrieben, die übrigen Sprachen maschinell übersetzt.
- Meldet die Wallbox einen Schlüssel ohne Wert (`null`, z. B. `pgrid`, solange sie keine PV-Daten bekommt), schreibt
  der Adapter kein `null` mehr in den Datenpunkt. Ein Datenpunkt wird erst angelegt, wenn die Wallbox einen Wert
  liefert; ein vorhandener Datenpunkt behält seinen letzten Wert.
- `info.friendlyName` hat die Rolle `text` (bisher `info.name`), weil er beschreibbar ist. `info.rssi` hat die Rolle
  `value.rssi` (bisher `value`).
- Zusätzliche API-Schlüssel, die sich nur in Groß-/Kleinschreibung unterscheiden (z. B. `tpa` und `TPA`), werden nur
  einmal verwendet.
- Das Readme verlinkt die Website des Herstellers.

### Auswirkungen

- Nach dem Update setzt der Adapter beim Start die neuen Namen und Rollen an seinen vorhandenen Objekten.
  Datenpunkt-IDs und Werte bleiben gleich.
- Datenpunkte, die gerade `null` enthalten, behalten das, bis die Wallbox einen Wert dafür meldet.
- Skripte, die an `null` einen fehlenden Wert erkannt haben, müssen stattdessen den Zeitstempel des Datenpunkts
  auswerten.

### Hintergrund

- Das sind Befunde aus der Prüfung für das ioBroker-Adapterverzeichnis: Jeder Datenpunkt braucht einen Namen in allen
  Sprachen, der Wert muss zum Typ passen, und die Rolle muss zu Lese- und Schreibrecht passen.
