## English

### What changed

- `energy.phases` now shows how many of the phases L1–L3 the wallbox has switched through to the car. The value is
  read from the API key `pha` (first three entries). Before, the state passed on the key `pnp`.
- The state is now named "Number of phases switched to the car" and has the value range 0–3.
- From this version on every release on GitHub comes with the ready-made package file
  `iobroker.goe-wallbox-<version>.tgz`.

### Impact

- While charging on three phases `energy.phases` shows **3**, on one phase **1**, and **0** when the contactor is open
  (not charging). Up to 0.1.0 it always showed 0.
- The state ID stays the same, so scripts, visualisations and history keep working. The new name and value range are
  applied automatically during the update. Instance settings are kept; no configuration is needed.
- The value counts the phases that are **switched**, not the ones that carry current: a car that charges on one phase
  at a wallbox switched to three phases shows 3. Which phases carry current is shown by `energy.currentL1` to
  `energy.currentL3`.

### Why

- The wallbox reports `pnp` as 0 while charging on one or on three phases (measured on a go-eCharger V4 with firmware
  60.5). The state therefore gave no usable information.
- Comparing the complete API status while charging on three phases, on one phase and while stopped showed that `pha`
  follows the switched phases exactly. It is a value the wallbox reports itself, not one calculated by the adapter.
- With the package file attached to the release the adapter can be installed without building it yourself.

## Deutsch

### Was sich geändert hat

- `energy.phases` zeigt jetzt, wie viele der Phasen L1–L3 die Wallbox zum Fahrzeug durchgeschaltet hat. Der Wert
  stammt aus dem API-Schlüssel `pha` (erste drei Einträge). Bisher wurde der Schlüssel `pnp` weitergegeben.
- Der Datenpunkt heißt jetzt „Anzahl zum Fahrzeug geschalteter Phasen“ und hat den Wertebereich 0–3.
- Ab dieser Version enthält jedes Release auf GitHub die fertige Paketdatei `iobroker.goe-wallbox-<Version>.tgz`.

### Auswirkungen

- Beim 3-phasigen Laden zeigt `energy.phases` **3**, beim 1-phasigen **1** und **0**, wenn das Schütz offen ist
  (kein Laden). Bis 0.1.0 stand dort immer 0.
- Die ID des Datenpunkts bleibt gleich; Skripte, Visualisierungen und Verlaufsdaten funktionieren weiter. Neuer Name
  und Wertebereich werden beim Update automatisch übernommen. Die Instanz-Einstellungen bleiben erhalten; es ist
  nichts einzustellen.
- Gezählt werden die **geschalteten** Phasen, nicht die stromführenden: Ein Fahrzeug, das an einer 3-phasig
  geschalteten Wallbox nur 1-phasig lädt, ergibt 3. Welche Phasen Strom führen, zeigen `energy.currentL1` bis
  `energy.currentL3`.

### Hintergrund

- Die Wallbox meldet `pnp` beim 1-phasigen wie beim 3-phasigen Laden als 0 (gemessen an einem go-eCharger V4 mit
  Firmware 60.5). Der Datenpunkt war dadurch ohne Aussage.
- Ein Vergleich des vollständigen API-Status beim 3-phasigen Laden, beim 1-phasigen Laden und im Stopp hat gezeigt,
  dass `pha` genau die geschalteten Phasen wiedergibt. Das ist ein Wert, den die Wallbox selbst meldet, keine
  Berechnung des Adapters.
- Mit der Paketdatei im Release lässt sich der Adapter installieren, ohne ihn selbst zu bauen.
